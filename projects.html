The Stalker

in progress

Unity · C#

Premise

A narrative escape-room-style puzzle game, built as part of the Video Game Development Club.

Tools & skills

Unity, C#, interface-based design, abstract classes, singleton pattern.

Responsibilites

As the lead programmer, my responsibilities included contributing my code, designing the software architecture, assigning weekly tasks, and holding the other programmers accountable through weekly check-ins.

Challenges

The first iteration of the player interaction was simple, relying on tags on interactable objects to drive the system. However, once other scripts began using tags, the system broke down, since Unity doesn't allow multiple tags on a single object.

The player collects and uses items throughout the game, and the item states and UI updates had to stay in sync across multiple scene loads.

Solutions

I refactored collision detection and the interaction system to be interface-based over tag-based, using colliders to build a live list of nearby interactables and resolving which one to interact with at runtime. Tag conflicts were eliminated.

I implemented the inventory around an abstract Item base class, allowing the core logic to remain consistent when presented with different items. A singleton manager maintains a persistent inventory across scene loads, so the item states and UI elements stay consistent.

Glorp's Heist

1st place — game jam

Unity · C#

Premise

A guard-patrol puzzle game where players navigate around guards walking fixed paths, timing their movement to stay out of sight.

Tools & skills

Unity, C#, vision/detection systems, raycasts, modular tooling, working under time pressure.

Challenges

As a game jam project, we had very little time to spend on level design itself. Hardcoding guard behaviour for each level would make code refinements time-consuming, so more modularity was needed.

The modularity of the guard patrols caused a second issue with guard vision. The vision cones needed to update in real-time to create responsive, fair gameplay.

Solutions

I deisgned the guard patrol system with many easily adjustable options, allowing for quick on-the-fly adjustments to paths and timings. It functions through the Unity inspector, allowing for modifications without touching the code, allowing for rapid iterations. The overall function is similar to that of a level editor.

To keep vision cones accurate against changing geometry, I used raycasts and colliders for realistic, responsive live updates and detection.

Night at the White House

finished — game jam

Unity · C#

Premise

A trash-collecting endless roguelike where players clear rooms to earn trash, buy upgrades, and eventually win.

Tools & skills

Unity, C#, procedural generation, minigame design, texture maps, mouse tracking

Challenges

Using a single lacked novelty for the user and would've gotten stale fast, so we needed rooms that felt different on different runs to keep gameplay fresh.

One of our minigames involved wiping dirt off a picture frame. Having no starting point, so I needed to learn how to implement this feature.

Solutions

I built three distinct room layouts, which then had randomized trash and trap spawns within specific areas over a collider. Rooms are randomized following a seed, and the map of all rooms is tracked using hashmaps and a registry script, to ensure fast runtime even in longer playthroughs.

To cause the effect of cleaning dirt, I created a dirty render texture, which the player then paints onto using mouse tracking with a texture mask, revealing the sprite underneath.
